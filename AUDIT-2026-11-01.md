## 3. Code review — B− (new agent path A−)

Full report: [.audit/findings/code-review.md](.audit/findings/code-review.md). **No Critical findings.** The new markdown/generator path is **approved** with one headers follow-up; the rest is accumulated debt.

### Required

- **R-1 — No security headers on page responses, and `_headers` cannot supply them.** `public/_headers:1-2` only sets a content type for `/site-description.jsonld`. Because `_routes.json` routes all page URLs through `_worker.js`, Cloudflare's documented rule applies: custom `_headers` are **not applied to Pages Functions responses** ([Pages Headers docs](https://developers.cloudflare.com/pages/configuration/headers/)). Emit `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options` in the worker; keep `_headers` for static assets (and add `Content-Type: text/markdown; charset=utf-8` for `/_markdown/*`). A full CSP needs a separate decision (9 inline Next bootstrap scripts + inline GA).
- **R-2 — GA4 loads unconditionally, including `npm run dev`, with a hard-coded ID** (`src/app/layout.tsx:70-81`, `src/lib/site.ts:6`). The project's own plan recorded GA as blocked on a privacy decision (`SEO_IMPLEMENTATION_PLAN.md:459`). Gate on `NODE_ENV === 'production'` and move the ID to build/deploy env.
- **R-3 — No site privacy/cookie disclosure.** The only policy is the unrelated Track My Salah app policy (noindex, unlinked). GA4 sets cookies on every visit with no consent/disclosure — a compliance risk depending on jurisdiction (legal advice out of scope).
- **R-4 — Build config ambiguity/stale scripts:** duplicate `postcss.config.js` (with redundant `autoprefixer` under Tailwind v4) and `postcss.config.mjs`; `tailwind.config.js` is never loaded (v4 CSS-first) and references nonexistent fonts; `npm start` cannot work with `output: 'export'`; `npm run preview` serves the repo root, not `out/`. Fix package scripts and dependency sections (`generate-markdown` runtime deps are in `devDependencies`, build tooling in `dependencies`).
- **R-5 — ~7.9 MB of unreferenced images deployed** (verified list: `images/hero/landing_screen_background.png` 4.9 MB, `layla-showcase/layla-editorial-hero-v1.png` 2.0 MB, notebook sheets, `signal/layla-premium-*`, `signal/layla-beauty-coach.webp`) + **Oswald font loaded/preloaded everywhere but referenced only by 3 dead selectors** (`globals.css:664,717,1151`). Only Oswald is safe to drop — Space Grotesk / Geist Sans / studio-page / signal vars are live.
- **R-6 — Dead code:** six unused files ≈432 LOC (`TextCanvas.tsx`, `Reveal.tsx`, `hooks/useReveal.ts`, `hooks/useTheme.ts`, `media/ProjectHero.tsx`, `BrutalButton.tsx`); ~211 of ~349 top-level rules in `globals.css` (~49%) match no TSX class; unused `words`/`image`/`note`/`icon` data fields; abandoned theme-toggle CSS.

Generate at build from the same page map: entity facts, one-line description of `bruh.ae`, curated page list with Markdown entry points; advertise via `Link` headers.
- **No alternate-markdown discovery links** anywhere (only README `curl` instructions). Add per-page `Link: </_markdown/…md>; rel="alternate"; type="text/markdown"` from the worker.
- **Frontmatter** (`scripts/generate-markdown.mjs:37-45`) emits only `title/description/url`; lift `author`, `datePublished`, `dateModified` from the Article JSON-LD it already collects.
- **Date concatenation bug:** `Commentary / 03July 16, 2026` and `By Adam20265 min read` in generated Markdown — adjacent inline spans without separators (`src/app/writing/[slug]/page.tsx:83-96`, `src/app/writing/page.tsx:33-36`). Fix in JSX (helps humans too) + regression test.

Add `Content-Location`, and optionally `X-Markdown-Tokens`/`Content-Signal` for parity with Cloudflare's native "Markdown for Agents" ([changelog 2026-02-12](https://developers.cloudflare.com/changelog/post/2026-02-12-markdown-for-agents/)).

**Safe / conventional (do these):**

2. Rewrite `/about`: H1 includes "Adam Ahsan", one-sentence definition, facts `<dl>` (location, focus, current work, selected work, contact, profiles), "last updated", profile links; add `ProfilePage`.
3. One declarative paragraph on the homepage + `/about`: *"Adam Ahsan is a Dubai-based builder working on AI products and software… bruh.ae is his personal portfolio: selected work, commentary, and experiments."*
4. A `/facts` + `/facts.json` press kit: canonical one-liner, 50/150/400-word bios, role, location, selected work, contact, profile links, last-verified date. Your Markdown mirror makes it agent-readable for free.
5. A short "Who is Adam Ahsan?" Q&A page (or Q&A block) — one-sentence answers match how models query; FAQ rich results are restricted but LLM extractors read the text fine.
6. Cross-web consistency: GitHub display name "Adam Ahsan" + website `https://bruh.ae` + text profile README (currently image-only) + X handle; LinkedIn headline/About aligned; Substack display name "Adam Ahsan" + site link; Medium bio + site link; link `bruh.ae` from the Qeemat README. `rel="me"` on outbound profile links.

- **Earned third-party mentions**: podcast transcripts/bios, conference speaker pages, guest posts with author bio, Dev.to/Hashnode cross-posts — the strongest durable entity signal because it is independent. Slow, but it is what actually produces knowledge panels.

Using "Adam Ahsan" as the site name and `alternateName: ["bruh.ae","BRUH"]` aligns everything Google/AI reads — this is the single highest-leverage naming change, and it contradicts the old plan decision (§9), which needs updating anyway.
