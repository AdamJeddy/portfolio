Built result: `out/about.html` `<title>About — Adam Ahsan</title>` but **`og:title="About"`, `twitter:title="About"`** (same for Contact, Projects, Commentary, Layla AI, Qeemat and all articles). `og:site_name` is "Adam Ahsan", which masks this on some platforms, but X/Twitter cards and many previews show the bare fragment — undermining the very entity signal this branch ships.

## 5. Is `.audit/verify-release.mjs` meaningful or a rubber stamp?

**Meaningful, not a rubber stamp.** It executes 77 assertions against real built files, `JSON.parse`s every JSON-LD block, compares exact strings/values (`author @id`, `+04:00` dates, `mainEntityOfPage` object shape, homepage `Person @id`, route list cleanliness, `Link` headers, security headers, `Vary`, HEAD, 404 passthrough, deleted-asset absence, WebP `srcset`, no broken internal links), and imports the generated worker with a file-backed ASSETS mock. It would catch most regressions of this feature.

**However it has real gaps** (all found defects against a fresh `out/` would have slipped through, and R-1 did):
1. **No `og:title`/`twitter:title` consistency check** — would have caught R-1 (`:24-54` only checks `<title>`/description/canonical/robots/h1/JSON-LD; `:117-121` only checks body/headers).
2. Title/description/canonical **uniqueness** is assumed, not asserted (I verified separately).
3. Fixed 12-file page list (`:24`) — a new/removed route is silently unchecked.
4. "No broken internal links" (`:135-150`) scans only those pages, only `href|src`; no Markdown/`llms*`/CSS `url()` targets.
5. No image dimension/byte-size assertions for the "81 KB/34 KB/42 KB" claims; no `og:image:width/height` check.
6. Sitemap check counts `<lastmod>` only; doesn't compare the URL set to canonicals or validate `lastmod` semantics.
7. No `robots.txt` content check and no live-managed-robots check (the riskiest SEO claim).
8. No negative test of the non-canonical URL variants (`/about/`, `/about.html`) after `_routes.json` was narrowed; README's 308 claim is untested by the script.
9. It cannot test Cloudflare `_headers` application or true CDN behavior (local mock only).
Add 1–4 as cheap assertions before the next release; the rest are deploy-runbook items.
